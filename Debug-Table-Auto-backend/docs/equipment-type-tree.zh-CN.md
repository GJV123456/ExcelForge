# ExcelForge 设备类型树形关系

本文档对应当前 SQLite 数据库中的设备目录配置，供后端、前端联调和规则维护人员核对。

## 1. 数据层级

```text
设备类型（equipmentType）
└── 子类型（equipmentSubtype）
    └── 状态/动作（equipmentStatus）
```

前端解析 Excel 后传递的字段对应关系：

| 前端字段 | 目录层级 | 说明 |
|---|---|---|
| `equipmentType` | 设备类型 | 例如：烟感、监视模块、防火阀 |
| `equipmentSubtype` | 子类型 | 例如：吸气式主机、电动防火阀、AFC；没有子类型时为空 |
| `equipmentStatus` | 状态/动作 | 例如：预警、报警反馈、开启控制命令；识别不到时为空 |

## 2. 基础设备类型

以下设备类型没有配置子类型，状态/动作为空或直接由规则匹配处理：

```text
烟感
温感
手报
消火栓
风阀
```

## 3. 设备类型直接对应的状态/动作

排烟机和加压送风机没有子类型，状态/动作直接挂在设备类型下：

```text
排烟机
├── 运行状态
├── 手自动切换状态
└── 开启控制命令

加压送风机
├── 运行状态
├── 手自动切换状态
└── 开启控制命令
```

## 4. 防火阀

```text
防火阀
├── 电动防火阀
│   ├── 动作状态
│   └── 关控制命令
└── 手动防火阀
    ├── 动作状态
    └── 动作反馈
```

手动防火阀的原始表可能使用“动作状态”或“动作反馈”，前端会把该字段传给后端，后端按状态选择对应规则。

## 8. 前端读取接口

### 获取完整树

```http
GET /api/catalog/equipment-hierarchy
```

返回结构：

```json
{
  "data": [
    {
      "id": 42,
      "code": "TYPE_MONITOR_MODULE",
      "name": "监视模块",
      "description": "",
      "sortOrder": 12,
      "isEnabled": true,
      "statuses": [],
      "subtypes": [
        {
          "id": 1,
          "parentEquipmentTypeId": 42,
          "code": "42_01",
          "name": "吸气式主机",
          "sortOrder": 1,
          "isEnabled": true,
          "statuses": ["预警", "火警", "故障", "远程复位"]
        }
      ]
    }
  ],
  "meta": {"count": 20}
}
```

### 按父类型获取子类型

```http
GET /api/catalog/equipment-types/{equipmentTypeId}/subtypes
```

### 获取责任专业

```http
GET /api/catalog/disciplines
```

规则输出结果中的 `responsibleDisciplines` 由后端一起返回，前端不需要写死责任专业。

## 9. SQLite 表对应关系

| SQLite 表 | 作用 |
|---|---|
| `equipment_types` | 设备类型主表 |
| `equipment_type_subtypes` | 设备类型与子类型关系 |
| `equipment_type_statuses` | 直接挂在设备类型下的状态/动作，例如排烟机 |
| `equipment_subtype_statuses` | 挂在子类型下的状态/动作，例如吸气式主机的预警 |
| `test_contents` | 测试内容规则 |
| `operation_steps` | 操作步骤 |
| `result_outputs` | 输出结果 |
| `disciplines` | 责任专业 |

```text
equipment_subtype_statuses：96 条
equipment_type_statuses：6 条
```
